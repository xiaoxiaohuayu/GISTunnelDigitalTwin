- [完整方案](隧道数字孪生_视频还原方案.md)。
- [视频逐段分析](video-analysis/视频逐段分析.md)。

截至 2026-10-20，用户已批准搭建 Vue 3 + TypeScript + Three.js + Cesium 基础工程，代码已落地，参见根目录 README.md。当前不包含模型、设备事件或数据看板；扩大实施范围按用户后续指示执行。

Gortex 已按用户要求卸载，用户明确要求不要调用。不要重新安装、连接或把它作为工作前提。

## 2. 不可变更的重点

1. 保留双洞入口、山体、管理建筑、道路和隧道内部的参考布局；同时匹配相机和光照。
2. 主界面保留左右六边形分类菜单、青色标题和底部导航，选择态为黄色。
3. 严格保留 11 类设备和 12 类事件的顺序及名称。第二设备名称识读有疑问，按证据文档处理。
4. GIS 包含地球/地形地图、双向线路、摄像头点位、上下各 8 格视频和返回场景。
5. 漫游要能观察检测门架、粉红覆盖体、白色路面检测区、设备引线标签及持续车流。
6. 看板出现后中央三维继续运行，图表由数据绘制。
7. 不使用静态截图替代三维，不用单一发光管道替代隧道模型，不用空壳按钮充数。
8. 原视频的水印、讲解字幕、录制提示和穿模故障不属于产品要求。
9. 不确定的字段、地理位置、按钮含义和设备细节必须显式记录，不自行补成“视频已确认”。

## 3. 推荐落地顺序

用户批准后，先检查实际文件、适用 AGENTS.md、工具和 Blender 版本，再建立最小 Web 工程。推荐 Vue 3 + TypeScript + Vite、Three.js、独立 Cesium 页面、ECharts、Blender GLB。版本以实施当日稳定且相互兼容为准。

第一批交付只做入口与短洞内的高保真样板、核心 HUD、两个固定相机。输出同视角对照，确认几何和画面后再扩展全部设备事件。若缺原资产，先重建关键模型，不用图库模型草率宣称还原完成。

接下来按主方案阶段推进设备/事件、漫游、GIS/监控、看板、优化。真实接口接入单独验收。不要在视觉样板之前先写权限后台、工单系统或通用配置平台。

Three.js 与 Cesium 分模式渲染，统一 entityId/deviceId/cameraId 与地理锚点。演示数据固定可重复，标记 simulation；真实接入标记 live。未知地理位置标记演示位置。

## 4. 需要维护的交付记录

实现开始后再创建以下记录，当前不预建空文件：

- 资产清单：源 .blend、GLB、贴图、来源和使用许可、节点命名、未还原项。
- 功能核对表：每个入口的参考时间、实现位置、测试步骤、结果。
- 视觉对照：入口、洞内、风机故障、施工、火灾、GIS、看板的参考与实现图。
- 数据说明：真实/演示来源、单位、坐标系、桩号方向、统计时间窗口。
- 性能记录：实际电脑和浏览器、分辨率/DPR、帧率、16 格视频压力、切换后的资源占用。
- 启动与演示说明：可直接执行的命令和还原视频流程的操作顺序。

不能把“构建成功”“页面能打开”作为 1:1 完成的证据。需要交互测试、参考截图比对和实际浏览器运行。性能目标是计划值，未测量不能写已达标。
