# 隧道配置、设备台账与场景编辑

配置与原精细场景使用同一渲染入口。`configuredMap.ts` 的独立简化场景已经移除。保存配置继续使用原有灯具、衬砌贴图、洞口、遮雨棚、标牌、车道指示器和控制状态。

## 使用方式

1. 右上角“配置与台账”维护项目名称、入口中心经纬度、高程、线路方位、纵坡和物理洞筒。每个洞筒独立维护起止桩号、车道宽度、车道数量和方向；同一洞筒可以有正反向车道。
2. 减少车道后，页面列出失去所属车道的设备。重新指定车道，或明确删除后才能保存。删除洞筒时会同时列出关联横洞和门，并要求确认。
3. 台账记录稳定 ID、编号、类型、桩号、高度、朝向和安装参照。安装参照包括车道、左右墙面、路缘、拱顶、场地和待确认；改变道路宽度时保留相对参照的人工偏移。
4. 从设备详情点击“调整位置”，显示 X 沿线路、Y 横向、Z 高度坐标轴。横向左负右正。拖动实时预览，也可以输入数值；保存写入浏览器，取消或 Esc 恢复原位置。保存失败保留草稿并显示错误，可以重试。
5. 横洞和停车带只沿线路调整。横洞维护另一端洞筒、桩号和关联门；移动时更新墙面开口、通道及门。停车带移动其拓宽与过渡段。开口冲突或越界禁止保存。
6. 批量录入支持 CSV / TSV，先预览、逐行校验，再加入草稿。JSON 可以导出、导入项目结构及台账。标识图片和独立控制设置继续保存在原 IndexedDB 记录中；当前 JSON 文件不包含这两类独立记录。

## 更新与资源所有权

- `DeviceInstance` 以安装参考点管理模型、屏幕、灯具及检测范围的变换；连续修改使用原始变换计算，避免重复叠加位移。
- 普通设备位置编辑更新现有实例，不修改 Vue 根组件 key，不销毁 Viewer，也不使用整场景加载遮罩。
- 车道配置更新受影响洞筒的道路与断面，重新布置洞口。增加、减少常规设备使用实例增删；场地设备和结构设施增删、洞筒拓扑及地理线路改变仍走场景资源重建，但保留 Viewer 和相机。
- 灯具由台账记录创建，外壳、支架与发光面属于同一可移动实例。路灯保持原组合资产中的独立节点，灯头光晕与地面光斑同步变换。
- 资源释放排除 Cesium 自身管理的 PrimitiveCollection，分别释放模块创建的模型、实体、屏幕、监听器和临时 GLB URL。

## 兼容与边界

配置版本升级为 2。读取旧版本时保留设备 ID、位置与编号，建立安装参照和已知横洞关联；无法确定的安装关系在台账中显示“待确认”。首次保存升级版本时，将旧版本另存为 `tunnel-project-v1-backup`。

支持 1～2 个物理洞筒、每洞 1～6 条车道和直线线路。设备可布设至洞口前后 240 m。当前每洞支持一处停车带，不支持曲线线形、断链或后台协议。亮度连续控制、卷帘门连续开度不在本轮范围内。

可编辑洞口地形使用独立的 `portal-terrain-editable.glb`，由 `scripts/prepare-editable-portal.cjs` 解码原资产中的土建网格生成，植被仍保留实例化。原 GLB、Blender 归档和归档校验值未改写。

本轮的实际检查结果见 [修正验收记录](repair-acceptance.md)。未验收项目不会仅凭构建通过标记为完成。
