# 车辆面板卡顿修复

## 修改

- 移除面板循环中的 `Scene.pickPosition()` 和同步 GPU 深度读取。隧道内用断面、停车带与横洞开口判断遮挡，地形使用 CPU 射线；关闭墙体、打开横洞门和地下查看的状态仍参与判断。
- 面板名称、模拟读数和可见目标每 250 毫秒刷新，状态或选择变化立即刷新。位置投影与引线按渲染帧更新，通过 `translate3d` 移动，绕开逐帧 Vue 更新、DOM 测量与布局重算。
- 车辆跨帧复用锚点，面板优先保留原有排序和相对位置，只有被抽屉等遮挡时才重新避让。

## 验证

同一测试浏览器、2560 × 1299 画布、detector-2 定位视角，车辆与场景持续运行：

| 场景 | 平均帧率 | 面板 pickPosition 查询 |
| --- | ---: | ---: |
| 修复前 | 约 0.9 FPS | 6 秒内约 48 次 |
| 修复前临时跳过深度读取 | 约 11.7 FPS | 跳过 |
| 修复后稳定采样 | 约 11.4 FPS | 0 次 |

修复后 6 秒采样包含 69 个帧间隔，车辆面板位置变化 69 次；帧间隔中位数 82.4 毫秒，95 分位 84.3 毫秒。仍采到一次 1067.5 毫秒长帧，不能据此声称整个三维场景已无卡顿或达到 60 FPS。该测试窗口的数据也不代表所有设备和视角。

首次修复后采样同时监测了 WebGL 深度读取，面板 pickPosition 与 readPixels 均为 0；Vue 信息数据低频刷新，而车辆面板位置逐帧变化。CPU 地形射线另外采样 90 次合计约 7.7 毫秒，最大单次约 0.4 毫秒。

31 项测试及生产构建通过。新增回归测试覆盖面板稳定位置、抽屉避让、同洞与异洞遮挡、横洞门开闭、拱顶、停车带、洞口和关闭墙体。
